## Semantic problem

`INSUFFICIENT_DATA` is an analytical-confidence statement. `OUT_OF_STOCK` is an observable availability statement.

Replacing the latter with the former mixes two dimensions and can hide a factual stockout merely because demand history is incomplete.

## Proposed Founder B decision A

**Recommended rule:** keep availability truth and analytical confidence separate.

When `usable_quantity <= 0`:

- primary availability state: `OUT_OF_STOCK`;
- evidence qualifier: `INSUFFICIENT_DATA` when demand/forecast evidence is insufficient;
- UI wording: **“Hết hàng · thiếu dữ liệu nhu cầu”**;
- do not compute days of supply, reorder urgency, or recommended order quantity without sufficient demand evidence.

Suggested human action split:

- if another warehouse has usable stock: **review internal transfer / redistribution**;
- if organization-wide usable stock is zero: **procurement + pharmacy/clinical review**;
- no automatic order quantity until demand evidence is adequate.

- [ ] **A1 APPROVE** — `OUT_OF_STOCK` remains primary when usable quantity is zero; `INSUFFICIENT_DATA` becomes a qualifier.
- [ ] **A2 MODIFY** — provide alternative precedence / wording.

## Semantic problem

Expiry date is direct evidence and does not require a demand model to know that a lot is approaching expiry. However, **quantity likely to expire unused** does require demand/consumption evidence.

Therefore these two statements must not be conflated:

1. **Time-window risk:** “this lot expires in N days” — directly evidenced.
2. **Expected wastage:** “X units / Y VND will likely expire unused” — not supportable without adequate demand evidence.

## Proposed Founder B decision B

**Recommended rule:** preserve expiry warning precedence as a time-window safety signal, while explicitly limiting confidence.

Suggested behavior:

- preserve `EXPIRY_RISK` when an active usable lot is within configured expiry windows;
- retain lot-level severity (`CRITICAL / HIGH / WARNING`) based on time-to-expiry policy;
- attach qualifier `TIME_WINDOW_ONLY` or **“Thiếu dữ liệu nhu cầu”**;
- do **not** populate or present `quantity_at_risk`, `value_at_risk`, avoidable-waste claims, or forecast-based urgency until sufficient demand evidence exists;
- recommend FEFO/manual transfer/review rather than automatic disposal or procurement action.

# Proposed two-axis status model

Instead of forcing every fact into one status string, the target model should expose:

| Dimension | Example values |
|---|---|
| Availability | OUT_OF_STOCK / LOW / HEALTHY / OVERSTOCK |
| Expiry | CRITICAL / HIGH / WARNING / NONE |
| Evidence confidence | SUFFICIENT / LIMITED / INSUFFICIENT_DATA |
| Recommendation | TRANSFER_REVIEW / PROCUREMENT_REVIEW / FEFO_REVIEW / NONE |

This preserves direct truths while preventing unsupported inference.

Example display:

- **Hết hàng** · `Thiếu dữ liệu nhu cầu` · `Có tồn kho ở kho khác → xem xét điều chuyển`
- **Cận hạn HIGH** · `TIME_WINDOW_ONLY` · `FEFO / rà soát điều chuyển`
